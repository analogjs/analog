# Points for Brandon

[analogjs/analog#2521](https://github.com/analogjs/analog/pull/2521) now includes the qualified SSR correction, automatic fast-mode behavioral reloads, lazy Effect runtimes, optional warming of used SSR compilers and a narrowly qualified native stylesheet path. The adoption decision remains in [analogjs/analog#2519](https://github.com/analogjs/analog/issues/2519). The [current p95 sprint report](packages/vite-plugin-angular/HMR_P95_SPRINT.md) owns the latest measurements, commands and evidence boundaries; the integration report retains the earlier cohort.

1. **Effect has a concrete compiler-lifecycle use case.** Sessions own watchers, native callers, resources and a runtime; the scheduler serializes compilation, coalesces edits and coordinates reads with the latest generation. Close drains admitted native work, and restarting creates independent ownership. Effect supplies composition, scoped fibers and the test clock; Analog still implements compiler policy. [Session tests](packages/vite-plugin-angular/src/lib/compiler-session.spec.ts), [scheduler tests](packages/vite-plugin-angular/src/lib/compilation-scheduler.spec.ts).

2. **The identified SSR and fast stale-output defects are fixed.** Every loaded SSR query variant and importer is invalidated with file timestamps. Known lazy owners retain unrelated modules. Old pending transforms cannot satisfy new readers or overwrite newer results. Fast methods, fields, constructors, dependencies, directives and pipes reload automatically with updated behavior. The five owner/query/pending regressions and six browser behavior cases are explicit proof boundaries.

3. **Loading costs are reduced, with measurements kept separate.** Supported Effect subpaths reduce loaded code and heap. ManagedRuntime allocation moves to first execution, while resource registration still works beforehand. An empty include result is reused until add/unlink/config invalidation. Schema and the direct Effect dependency remain. The latest import medians change by -10.7% to -10.4%; construction, first/warm builds and CPU are reported separately. Fast compilation now shares unchanged ASTs, and the Compilation API normalizes diagnostics once per compilation.

4. **SSR warming helps a specific request pattern.** Only a previously used development SSR environment is eligible. A scoped 75 ms delay follows settled client update dispatch; reads bypass the delay. Tests cover failure visibility, recovery, coalescing, cancellation, drain and restart. The fixed 0/250/1000 ms idle cohorts include both server-first and browser-first startup; the report records foreground wait, CPU and memory for each compiler and interval. Speculation can spend CPU when no request follows, and fast mode shows no consistent benefit. `experimental.ssrHmrWarmup: false` keeps compilation strictly on demand. Independent server startup still costs time.

5. **CSS preservation claims now distinguish actual DOM identity from counters.** Native link updates preserve focus, selection, DOM nodes and nested child state in the qualified shared-Sass fixture, including repeated edits, lazy creation and template → CSS → template. They require existing integration externalization: ngtsc on Angular 20–22/Vite 6–8 or Compilation API on Angular 21–22/Vite 7–8. Automatic externalization of ordinary styles missed the template-latency gate, so ordinary ngtsc, fast and API styles retain metadata updates. Metadata recreates views; ShadowDom and unsupported/failed paths can reload. `experimental.componentStyleHmr: 'metadata'` remains an escape hatch. [Capability table and tests](packages/vite-plugin-angular/HMR_INTEGRATION.md#stylesheet-capabilities-and-fallbacks).

6. **Overall correctness remains open after final CI exposed intermittent failures.** Angular 22/Vite 6.0 lost shared styles and emulated attributes after shared-resource edits; an exact fresh local replay passed without establishing a cause. Windows also timed out before the initial API ShadowDom render. Neither failure is resolved by prior passing runs. [Retained failure evidence](packages/vite-plugin-angular/HMR_P95_SPRINT.md#ci-follow-up-and-unresolved-correctness). **Local qualification is broad but bounded.** All 983 package tests, both typechecks, lint/build/artifact gates, 13 packed Linux tuples and the focused native/fallback/behavior checks pass. Nine new four-minute update windows, each within a five-minute total process cap, complete 540 edit pairs, 27 restarts and 900 queued shutdown calls. The dated Windows/CI snapshot is in the PR. These tests do not prove leak freedom or universal compatibility. Historical alpha/original-PR comparisons and old soaks remain separate from the new correctness-only-control comparison. **The strict 5% acceptance gate remains unmet: 6/12 browser cells pass all four latency limits; first/warm build gates pass. The latency misses remain explicit in the linked report. No overall speedup or completed performance-acceptance claim is made.**

Effect `4.0.0-rc.112` remains a prerelease dependency with installation and maintenance costs. Historical package-file accounting was 47,533,320 bytes; this is neither download size nor incremental pnpm-store space. Public `angular(options): Plugin[]` usage remains native, packed root declarations do not expose Effect services, and checked browser/application graphs exclude Effect. Internal shipped declarations still contain Effect types. There is no equivalent optimized Effect-free comparison, so the benchmarks do not isolate Effect's performance contribution. The remaining decision is whether its lifecycle and testing model justify the dependency and maintenance cost.
