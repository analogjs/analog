1. **Effect has a concrete compiler-lifecycle use case.** Sessions own watchers, native callers, resources and a runtime; the scheduler serializes compilation, coalesces edits and coordinates reads with the latest generation. Close drains admitted native work, and restarting creates independent ownership. Effect supplies composition, scoped fibers and the test clock; Analog still implements compiler policy. [Session tests](packages/vite-plugin-angular/src/lib/compiler-session.spec.ts), [scheduler tests](packages/vite-plugin-angular/src/lib/compilation-scheduler.spec.ts).

2. **The identified SSR fetch and fast stale-output defects have targeted fixes.** Every loaded SSR query variant and importer is invalidated with file timestamps. Known lazy owners retain unrelated modules. Old pending transforms cannot satisfy new readers or overwrite newer results. Fast methods, fields, constructors, dependencies, directives and pipes reload automatically with updated behavior. The five owner/query/pending regressions and six browser behavior cases are explicit proof boundaries.

3. **Loading costs are reduced, with measurements kept separate.** Supported Effect subpaths reduce loaded code and heap. ManagedRuntime allocation moves to first execution, while resource registration still works beforehand. An empty include result is reused until add/unlink/config invalidation. Schema and the direct Effect dependency remain. The previous cohort import medians change by -10.7% to -10.4%; construction, first/warm builds and CPU are reported separately. Fast compilation now shares unchanged ASTs, and the Compilation API normalizes diagnostics once per compilation.

4. **SSR warming helps a specific request pattern.** Only a previously used development SSR environment is eligible. A scoped 75 ms delay follows settled client update dispatch; reads bypass the delay. Tests cover failure visibility, recovery, coalescing, cancellation, drain and restart. The fixed 0/250/1000 ms idle cohorts include both server-first and browser-first startup; the report records foreground wait, CPU and memory for each compiler and interval. Speculation can spend CPU when no request follows, and fast mode shows no consistent benefit. `experimental.ssrHmrWarmup: false` keeps compilation strictly on demand. Independent server startup still costs time.

5. **CSS preservation claims now distinguish actual DOM identity from counters.** Native link updates preserve focus, selection, DOM nodes and nested child state in the qualified shared-Sass fixture, including repeated edits, lazy creation and template → CSS → template. They require existing integration externalization: ngtsc on Angular 20–22/Vite 6–8 or Compilation API on Angular 21–22/Vite 7–8. Automatic externalization of ordinary styles missed the template-latency gate, so ordinary ngtsc, fast and API styles retain metadata updates. Metadata recreates views; ShadowDom and unsupported/failed paths can reload. `experimental.componentStyleHmr: 'metadata'` remains an escape hatch. [Capability table and tests](packages/vite-plugin-angular/HMR_INTEGRATION.md#stylesheet-capabilities-and-fallbacks).

6. **Overall correctness remains open.** Stable source reads, retained source gates and per-node pending SSR fetch retries now pass focused proofs, all 995 package tests, both typechecks, lint/build, six split-write SSR probes and nine four-minute soaks. The final packed Vite 8 run passes. A separate final Vite 6/ngtsc packed run retains browser revision 3 after its second restart expecting revision 4; all preceding SSR checks pass. Its cause is not established, and no rerun replaces the failed observation. Earlier Windows initial-render failure evidence remains retained. **Current-source performance is unmeasured.** The previous completed cohort met all four browser limits in 6/12 cells and all first/warm build gates; it does not qualify the latest repairs. The restart task must resolve correctness, then run the fixed comparison at the unchanged 5% limits. [Current evidence and remaining obligations](packages/vite-plugin-angular/HMR_WRITE_FIX.md).
